# 운행시간 시뮬레이션 검토 — 2026-09-07

## 원인과 수정

이전 구현은 정류장과 KML 꼭짓점 사이의 거리를 비교하고, 정류장 4개 단위로 경로를 다시 선택했다. 긴 선분의 중간에 있는 정류장이 다른 회차의 꼭짓점에 붙을 수 있었으며, 구간이 바뀔 때 앞에서 사용한 선형을 다시 포함했다. 원본 KML이 잘못되었다고 단정할 수 있는 문제가 아니었다.

- 정류장을 각 선분 위에 투영해 실제 선형 위치를 찾는다.
- 전체 정류장 순서를 한 번에 매칭하고, 선형상의 누적 거리가 뒤로 가지 않게 한다. 정방향과 역방향을 모두 검토한다.
- 거리 제곱으로 정류장 위치 오차를 평가한다. 이동거리는 거의 같은 후보의 동률 해소에만 사용한다. 실제 순환 구간을 최단 경로라는 이유로 잘라내지 않는다.
- 확정한 정류장 사이 선형을 구간별 계산, 시간 배분, 지도 표시에서 재사용한다.
- 같은 좌표의 별도 정류장을 삭제하지 않는다. 해당 구간의 주행거리는 0m이며 정차시간은 유지한다.
- 첫 정류장이 KML 시작점과 다른 순환노선은 한 바퀴의 시작 위치를 옮긴다. 양 끝이 30m 이내인 선형만 대상으로 하며, 연결한 간격이 1m를 넘으면 결과에 그 길이를 알린다.
- 서로 떨어진 별도 LineString은 임의의 도로로 이어 계산하지 않고 연결 확인을 요청한다.

## 판단 범위와 안내

- 정류장–선형 매칭 허용 거리: 150m. 50m 초과이면 결과·지도·계산 로그·엑셀에 위치 확인 안내를 남긴다. 매칭 불가 또는 순서 불일치는 계산 오류로 알린다.
- 첫·마지막 정류장 바깥의 제외 경로가 50m를 초과하면 안내한다.
- 정류장 간 선형이 1km를 넘고 직선거리(최소 기준 100m)의 5배를 초과하면 의도한 순환 구간인지 안내한다. 자동으로 지름길을 만들지 않는다.
- 중복노선 분석의 중심선 거리 20m 설정과 시뮬레이션의 정류장 매칭 허용 거리는 서로 다른 기준이다. 중복노선 분석 설정은 그대로다.
- 카카오 길찾기 모드는 기존 요청·강제 경유점 처리를 사용한다.
- 그린 경로 모드의 시간은 기존 권역·요일 평균속도, 지체율, 정류장 정차시간을 적용한 추정값이다. 실시간 교통이나 실제 버스 운행 적법성을 확인하는 기능은 아니다.

## 실제 KML 회귀 검증

입력: `중구 노선도_개선사항(26하반기)  복사본.kml`, 9개 노선.

| 노선 | 원본 선형(m) | 수정 전 구간 합계(m) | 수정 후 구간 합계(m) |
|---|---:|---:|---:|
| 1 | 6,760.9 | 6,574.8 | 6,768.0 |
| 1-1 | 8,564.3 | 19,724.9 | 8,564.3 |
| 2 | 6,963.7 | 15,254.7 | 6,963.8 |
| 3 | 6,137.8 | 6,137.8 | 6,137.9 |
| 4 | 8,050.1 | 8,050.1 | 8,050.2 |
| 5 | 8,797.9 | 13,628.9 | 8,757.3 |
| 6 | 6,635.0 | 6,635.0 | 6,642.6 |
| 7 | 7,420.3 | 10,399.5 | 7,420.3 |
| 8 | 6,163.9 | 6,144.5 | 6,145.3 |

구간별 소수점 반올림으로 0.1m 정도 차이가 생길 수 있다. 1·6노선은 순환 경로 끝 간격 7.0m·7.6m를 포함한다. 5·8노선은 실제 첫·마지막 정류장 위치까지 계산하므로 선 전체보다 약간 짧다.

1-1노선 구간 2는 4,437.4m → 1,105.7m. 다산동작은도서관에서 가온도서관까지 선형은 약 316m이다. 기존 평일 조건(13.9km/h, 지체율 9%, 기본 정차 26초)에서 구간 2의 총 시간은 390초(6분 30초)이며, 전체는 3,017초(50분 17초)다.

남은 위치 확인 사항: 1노선 충무아트센터의 선형 이격 약 55m, 8노선 소공누리센터 입구의 선형 이격 약 137m. 정류장 좌표를 임의로 변경하지 않고 결과에 안내한다.

## 검증 방법

`npm run check`로 구문 검사, `npm test`로 합성 경로 11개 검증. `SIMULATION_TEST_KML` 환경변수에 위 KML 경로를 지정하면 실제 노선 9개를 추가해 총 20개를 검증한다. 테스트는 앱의 실제 함수·상수를 로드하며 정류장/경로 조회만 테스트 입력으로 교체한다.

확인 항목: 긴 선분 중간 매칭, 왕복 선형의 중복 통과, 역방향, 완전 순환, 시작점 회전, 같은 좌표의 정류장, 가상 경유점, 단절 선형, 잘못된 순서, 과도한 정류장 이격, 카카오 모드 분리. 실제 노선별로 지도 선형 거리와 계산 거리, 구간 연결, 누적시간과 총시간 일치, 생성된 지도 창 스크립트의 구문, 엑셀 안내 포함 여부를 검사했다.

Render 배포 및 Git 커밋/푸시는 수행하지 않았다. 기존에 열린 결과 창은 이전 계산이므로 메인 화면을 새로고침하고 시뮬레이션을 다시 실행해야 한다.

## 경로보기 체크 상태 추가 검토

전체 선과 구간별 선이 독립적으로 중첩되어, 구간 체크를 해제해도 전체 선이 남았다. 구간 집중 보기 상태에서는 다른 구간을 체크해도 숨김 필터가 유지됐고, 새로 그릴 때 전체 선에 상단 체크 상태를 다시 적용하지 않았다.

표시 규칙을 아래처럼 통일했다.

| 조작 | 결과 |
|---|---|
| 원본 경로 / 분석 경로 | 해당 종류의 전체 선·구간 선을 모두 제어. 분석 화살표도 분석 경로 설정을 따름 |
| 체크한 구간만 표시 켬 | 전체 선을 숨기고 체크한 구간의 선·정류장·구간 이름만 표시 |
| 체크한 구간만 표시 끔 | 선택한 종류의 전체 선 표시, 구간별 선과 표식 숨김 |
| 구간 체크 변경 | 집중 보기를 해제하고 체크한 구간들을 표시. 구간을 켜면 구간 선택 모드도 켬 |
| 이 구간만 보기 / 원본·분석 구간 클릭 | 해당 구간과 필요한 경로 종류를 체크하고 집중 표시, 지도 범위 맞춤 |
| 체크한 구간 모두 보기 | 집중 보기 해제. 개별 체크 선택은 유지 |
| 재계산·지도 다시 그리기 | 같은 표시 규칙과 상단 체크 상태 재적용 |

구간 체크를 해제해도 다른 선택 구간과 물리적으로 겹치는 공통 선형은 계속 보일 수 있다. 이는 선택한 다른 구간의 경로다.

지도 초기 축척은 `map.getBounds()`로 얻은 기존 화면 영역을 확대하는 방식에서, 빈 `LatLngBounds`에 실제 보이는 경로 좌표를 넣는 방식으로 변경했다. 참고: [Kakao 지도 범위 재설정 공식 예제](https://apis.map.kakao.com/web/sample/setBounds/). 북쪽을 향한 삼각형의 회전각도 화면 좌표 기준으로 수정했다.

검증은 생성된 지도 창의 실제 스크립트를 실행하되 DOM과 Kakao 지도 객체를 테스트 대역으로 교체했다. 체크 상태 32가지 조합, 집중 보기 전환, 재렌더링 시 상태 유지, 지도 범위, 방향 화살표를 검증하는 6개 테스트를 추가했다. 실제 지도 타일이나 팝업 브라우저의 시각적 검증을 대신하는 테스트는 아니다.
